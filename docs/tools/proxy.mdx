Kael starts an isolated [mitmproxy](https://mitmproxy.org/) sidecar in every
sandbox session. Shell commands and the browser inherit `HTTP_PROXY` and
`HTTPS_PROXY`, and the generated CA is installed in the sandbox's system and
Chromium trust stores before the session is marked ready.

## Agent tools

| Tool | Purpose |
|---|---|
| `list_requests()` | Filter and page through captured HTTP traffic |
| `view_request()` | Inspect or search a raw request or response |
| `repeat_request()` | Replay a captured request with modifications |
| `list_sitemap()` | Browse the discovered host/path tree |
| `view_sitemap_entry()` | Inspect a sitemap entry and related requests |
| `scope_rules()` | Create and manage soft capture scopes |

## Filtering

`list_requests` accepts a `mitm_filter` value using mitmproxy filter syntax.
Common operators include:

| Expression | Meaning |
|---|---|
| `~m POST` | POST requests |
| `~d api\.example\.com` | Requests to one host |
| `~u /api/` | URLs whose full value matches `/api/` |
| `~c 5..` | Responses with a 5xx status |
| `~hq Authorization` | Request headers containing `Authorization` |
| `~bs "token|secret"` | Response bodies matching either word |
| `!~u "\.(css|js|png)$"` | Exclude common static assets |

Combine filters with `&`, `|`, `!`, and parentheses:

```text
~m POST & ~u /api/ & !~c 401
```

## Replay

`repeat_request` accepts request overrides for `url`, `params`, `headers`,
`body`, and `cookies`. A typical validation loop is:

1. Generate traffic with the browser, `curl`, or a scanner.
2. Locate the baseline with `list_requests`.
3. Inspect it with `view_request`.
4. Replay a controlled mutation with `repeat_request`.
5. Compare status, headers, response length, body, and timing.

## Python integration

Prefer the first-class tools above during a normal scan. For batch logic in a
sandbox Python script, import the image-baked `mitm_control` module:

```python
import asyncio

from mitm_control import list_flows, replay_flow


async def main():
    result = await list_flows(mitm_filter="~m POST & ~u /users/", first=20)
    for entry in result["entries"]:
        replay = await replay_flow(
            entry["id"],
            modifications={"headers": {"X-Testing": "kael"}},
        )
        print(entry["id"], replay["success"])


asyncio.run(main())
```

The module also exposes `view_flow`, `list_sitemap`, `view_sitemap_entry`, and
`scope_rules`. All helpers are asynchronous and return dictionaries.

## Scope rules

Scopes provide allowlist and denylist filtering for captured traffic:

```text
Allowlist: ["api.example.com", "*.example.com"]
Denylist: ["*.gif", "*.jpg", "*.png", "*.css", "*.js"]
```

Scope rules help reduce noise; they do not authorize a target or replace
network-level egress restrictions.
