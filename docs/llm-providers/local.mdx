---
title: "Local Models"
description: "Connect Kael to Ollama or an OpenAI-compatible local endpoint"
---

A local model can keep prompts and model responses on infrastructure you
control. Kael may still access authorized targets and optional search services,
so disable those integrations and restrict network egress when operating in an
air-gapped environment.

<Warning>
Kael depends heavily on reliable tool calling, long-context instruction
following, and multi-step planning. Confirm those capabilities with your model
and serving stack before using the result for a critical assessment.
</Warning>

## Ollama

1. Install [Ollama](https://ollama.com).
2. Pull a model that supports the capabilities above.
3. Configure Kael with the model's Ollama slug:

```bash
ollama pull <model>
export KAEL_LLM="ollama/<model>"
export LLM_API_BASE="http://localhost:11434"
```

Model availability changes with the Ollama catalog. Verify the exact slug with
`ollama list` after pulling it.

## OpenAI-compatible servers

For LM Studio, vLLM, or another OpenAI-compatible endpoint:

```bash
export KAEL_LLM="openai/<served-model-id>"
export LLM_API_BASE="http://localhost:1234/v1"
export LLM_API_KEY="local-placeholder-if-required"
```

Adjust the host, port, model ID, and credential behavior to match the server.
If the endpoint is on another machine, bind it securely and use a reachable URL
instead of `localhost`.
