---
title: "Configuration"
description: "Supported environment variables and config-file precedence"
---

Kael resolves configuration in this order, from highest to lowest priority:

1. Process environment variables
2. A `.env` file in the current working directory
3. The selected JSON config file
4. Built-in defaults

The default JSON path is `~/.kael/cli-config.json`. Select another file with
the positional `config` keyword:

```bash
kael ./app config /path/to/config.json
```

Provider-specific authentication variables such as `AZURE_API_KEY`, AWS
credentials, and Google Application Default Credentials are consumed by
LiteLLM; see the corresponding provider guide.

## LLM

| Variable | Default | Purpose |
|---|---:|---|
| `KAEL_LLM` | — | LiteLLM provider/model identifier, such as `openai/gpt-5.4` |
| `LLM_API_KEY` | — | Main provider credential; `OPENAI_API_KEY` is also accepted |
| `LLM_API_BASE` | — | Custom provider endpoint |
| `KAEL_REASONING_EFFORT` | `high` | `none`, `minimal`, `low`, `medium`, `high`, or `xhigh` |
| `LLM_TIMEOUT` | `300` | LLM request timeout in seconds |
| `KAEL_OPENROUTER_PROVIDER` | — | OpenRouter provider-routing preferences as a JSON object |
| `KAEL_VISION_LLM` | — | Optional dedicated vision-model identifier |
| `VISION_LLM_API_KEY` | Main key | Credential for the dedicated vision model |
| `VISION_LLM_API_BASE` | Main base URL | Endpoint for the dedicated vision model |

`OPENAI_API_BASE`, `OPENAI_BASE_URL`, `LITELLM_BASE_URL`, and
`OLLAMA_API_BASE` are accepted aliases for `LLM_API_BASE`.

## Container runtime

| Variable | Default | Purpose |
|---|---:|---|
| `KAEL_IMAGE` | `kael-sandbox:0.1.0` | Sandbox image tag |
| `KAEL_RUNTIME_BACKEND` | `docker` | Runtime CLI: `docker` or `podman` |
| `KAEL_AUTO_BUILD_SANDBOX` | `false` | Permit a missing default image to be built in non-interactive runs |
| `KAEL_CONTAINER_SOCKET` | Runtime default | Filesystem path to a Docker-compatible API socket |

Kael source-builds only its versioned default image. A missing custom image is
pulled by the selected runtime.

For rootless Podman:

```bash
export KAEL_RUNTIME_BACKEND=podman
export KAEL_CONTAINER_SOCKET="/run/user/$(id -u)/podman/podman.sock"
systemctl --user start podman.socket
```

Rootful Podman defaults to `/run/podman/podman.sock`. Docker uses the standard
Docker environment and socket when `KAEL_CONTAINER_SOCKET` is unset.

## Search integrations

| Variable | Default | Purpose |
|---|---:|---|
| `PERPLEXITY_API_KEY` | — | Enable Perplexity-backed web search |
| `TAVILY_API_KEY` | — | Enable Tavily-backed exploit search |
| `TAVILY_SEARCH_DEPTH` | `advanced` | `basic` or `advanced` |
| `TAVILY_MAX_RESULTS` | `10` | Maximum Tavily results |
| `TAVILY_INCLUDE_ANSWER` | `true` | Ask Tavily for a synthesized answer |
| `EXPLOITDB_MAX_RESULTS` | `15` | Maximum Exploit-DB results |
| `EXPLOITDB_TIMEOUT` | `60` | Exploit-DB timeout in seconds |

## Memory and tool loop

| Variable | Default | Purpose |
|---|---:|---|
| `KAEL_MEMORY_LEARNING_TTL_DAYS` | `90` | Learning retention; `0` disables expiry |
| `KAEL_MEMORY_MAX_LEARNINGS_PER_TARGET` | `500` | Per-target learning cap |
| `KAEL_PARALLEL_TOOL_CALLS` | `off` | `off`, `safe`, or `all` |
| `KAEL_TOOL_RESULT_MAX_CHARS` | `20000` | Soft size cap for one tool result |
| `KAEL_DEDUP_WINDOW_TURNS` | `1` | Window used to warn about repeated tool calls |

## Malware reverse engineering

| Variable | Default | Purpose |
|---|---:|---|
| `KAEL_RE_ANALYSIS_MODE` | `both` | `static`, `dynamic`, or `both` |
| `KAEL_RE_MAX_RUNTIME_SEC` | `120` | Maximum duration of one detonation |
| `KAEL_RE_NETWORK_MODE` | `controlled` | `off`, `controlled`, or `live` |
| `KAEL_RE_BLOCKED_CIDRS` | `["169.254.169.254/32"]` | JSON array of CIDRs blocked in controlled mode |
| `KAEL_RE_YARA_RULES_DIR` | — | Directory containing additional YARA rules |
| `KAEL_RE_ENABLE_MEMORY_DUMPS` | `true` | Allow memory dumps during detonation |

<Warning>
`live` malware networking permits unrestricted outbound traffic from the
sandbox. Use it only in a controlled lab with explicit authorization.
</Warning>

## JSON format

```json
{
  "env": {
    "KAEL_LLM": "openai/gpt-5.4",
    "LLM_API_KEY": "sk-...",
    "KAEL_REASONING_EFFORT": "high",
    "KAEL_RUNTIME_BACKEND": "podman"
  }
}
```

Keep credentials out of version control. Kael writes local run events and
reports under `kael_runs/`; no remote telemetry endpoint is configured by
these settings.
