---
title: "GitHub Actions"
description: "Run source-only Kael on a self-hosted or Docker-capable runner"
---

Kael v0.1 is source-only and builds a large local sandbox. Use a runner with a
Docker daemon, adequate disk space, and explicit permission to send authorized
scan traffic.

```yaml .github/workflows/security.yml
name: Kael security scan

on:
  workflow_dispatch:

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: actions/checkout@v4
        with:
          repository: Th4phat/kael-agent
          ref: v0.1.0
          path: .kael-src

      - uses: astral-sh/setup-uv@v5

      - name: Install Kael outside the scan target
        run: |
          mv "$GITHUB_WORKSPACE/.kael-src" "$RUNNER_TEMP/kael-src"
          uv sync --project "$RUNNER_TEMP/kael-src" --frozen

      - name: Run Kael
        env:
          KAEL_LLM: ${{ secrets.KAEL_LLM }}
          LLM_API_KEY: ${{ secrets.LLM_API_KEY }}
          KAEL_AUTO_BUILD_SANDBOX: "1"
        run: >-
          uv run --project "$RUNNER_TEMP/kael-src" kael "$GITHUB_WORKSPACE"
          non-interactive mode quick scope-mode diff diff-base origin/main
```

Prefer manual or tightly scoped workflows until you have reviewed the target,
network egress, cost limits, and secret exposure. Cache the Docker build on
trusted runners if repeated builds are too expensive.
