---
title: "CI/CD Integration"
description: "Run source-only Kael in controlled automation"
---

CI runners need Git, uv, Python 3.12 or 3.13, a Docker-compatible runtime, and
enough storage to build the local Kali-based sandbox. Kael's own CI uses Docker.

The generic flow is:

```bash
TARGET_DIR="$PWD"
KAEL_SRC="${RUNNER_TEMP:-/tmp}/kael-src"
git clone --branch v0.1.0 --depth 1 https://github.com/Th4phat/kael-agent.git "$KAEL_SRC"
uv sync --project "$KAEL_SRC" --frozen
KAEL_AUTO_BUILD_SANDBOX=1 \
  uv run --project "$KAEL_SRC" kael "$TARGET_DIR" non-interactive mode quick
```

Set `KAEL_LLM` and `LLM_API_KEY` through the CI platform's protected secret
store. Fetch full history when using diff scope.

## Exit codes

| Code | Meaning |
|---|---|
| 0 | Scan completed successfully |
| 1 | Setup or runtime error |
| 2 | Invalid input, or one or more findings in a non-interactive scan |

<Warning>
Do not run automated active testing against unapproved production targets. Limit
egress, concurrency, model spend, and the target scope explicitly.
</Warning>
